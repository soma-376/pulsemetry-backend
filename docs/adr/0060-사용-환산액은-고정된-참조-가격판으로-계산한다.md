# 0060. 사용 환산액은 고정된 참조 가격판으로 계산한다.

## Status

Accepted — 부분 대체: [ADR 0071](0071-서버-환산은-단일-카탈로그를-쓰고-가격판-기록을-제거한다.md)이 가격판 선택·기록 및 가격판 기반 재평가를 대체한다. 나머지 규칙은 유지한다.

기존 상태 근거: Accepted — 허브 ADR 0008(`current-public-reference-valuation`)의 backend 구현이다. [ADR 0020](0020-정규화-계약-2판은-관측을-식별하고-의미-컬럼으로-교체-저장한다.md) §3·§4의 가격 프로파일 선택과 관리 주체를 구체화한다.

## Context

- ADR 0020은 검증된 불변 가격 프로파일로만 추정 비용을 허용하지만, 가격표의 출처·소유·갱신은 정하지 않았다.
- 기존 `PricingStage`는 사건 시각(`source_time`)에 유효한 요금만 고른다. 현재 단가로 과거 사용량을 평가하려면,
  그 요금이 과거에 유효했다고 꾸미지 않는 별도 기준이 필요하다.
- 공급자 공식 문서로 직접 확인한 모델은 일부다. Codex 자동 검토(`codex-auto-review`)처럼 공개 단가가 없는 모델도
  실제 사용량에 섞여 있어, 공식 확인 모델만으로는 대부분의 사용량이 환산 미확인으로 남는다.

## Decision

1. 가격 프로파일은 사건 시각 기준(`EVENT_TIME`)과 참조 기준(`CURRENT_REFERENCE`)을 구분한다. 참조 기준은 프로파일에
   고정된 `referenceAsOf`로 요금을 고른다. 원천 시각을 바꾸거나 과거 유효 시작일을 만들지 않는다.
2. 기본 가격판은 `codeburn-0.9.24-reference-2026-10-16-v1`이다. Codeburn 0.9.24의 번들·보완 가격표와 명시적 별칭에서
   Claude·OpenAI/Codex 텍스트 토큰 단가를 추출해 고정 TSV(`pricing/codeburn-0.9.24.tsv`)로 둔다. 추출 스크립트와
   해시 명세(`docs/pricing/codeburn-import-manifest.json`)를 함께 보존한다.
3. 공급자 공식 문서로 직접 확인한 9개 모델(Claude 6개, `gpt-6-astra`, `gpt-5.6-luna`, `gpt-6-luna`)은 그 단가와
   요청별 장문 요율이 Codeburn 값보다 우선한다. 단가와 출처는 `docs/pricing/current-public-standard.md`가 담는다.
4. 별칭은 별도의 정확한 행이다. `codex-auto-review → gpt-5.5`는 환산 기준의 선택이며, 모델 동일성이나 실제 청구액의
   근거가 아니다. 원본 `model`은 바꾸지 않는다.
5. 정확한 모델 ID로만 가격을 고른다. prefix·유사 이름 매칭, 사용자 로컬 설정, 실행 중 가격 조회는 하지 않는다.
   카탈로그에 없는 모델, 검증되지 않은 토큰 의미, 필요한 성분의 누락은 null이다. 미가격을 0원으로 만들지 않는다.
6. Claude 캐시 생성은 공식 5분 쓰기 단가로 평가한다. 평가 기준일 뿐 실제 TTL이 5분이었다는 판정이 아니다.
   명시 0은 0, 양수는 5분 단가, 미보고는 null이다. Codeburn 표에 캐시 요율이 비어 있으면 Codeburn의 파생 규칙
   (쓰기 = 입력×1.25, 읽기 = 입력×0.1)을 적용해 수치로 고정한다.
7. 장문 요율은 공식 문서가 정한 모델에만 적용한다. 단일 요청의 전체 입력(uncached + read + create)이 272,000을
   초과하면 입력·캐시 단가 2배, 출력 단가 1.5배다. 여러 요청의 누계로 판정하지 않는다.
8. 가격판은 불변이다. 단가·모델 범위·평가 정책을 바꾸면 새 `pricing_version`을 만들고 `RowVersioning.NORMALIZER_REV`를
   올린다. 저장된 행은 자동으로 다시 계산되지 않는다. 기존 행의 재평가는 [ADR 0062](0062-저장된-사용량은-토큰-의미가-확인된-행만-재평가하고-나머지는-사유로-남긴다.md)를 따른다.
   현재 정규화 판은 9다. 2~8은 배포되지 않은 개발 판이라 결번으로 둔다. 같은 관측의 교체 우선순위이므로 낮추지 않는다.
9. ingest 조립이 `PULSEMETRY_PRICING_PROFILE` 이름으로 프로파일을 고른다. `none`은 계산하지 않음을 명시하고,
   알 수 없는 이름은 기동 오류다. 개발 중 만든 공시 가격판 v1~v4(`public-standard-global-reference-2026-10-16-v1`~`v4`)는
   같은 방식으로 선택할 수 있는 불변 값으로 남긴다. 로컬 검증 데이터가 이 판들을 참조한다. 배포 기본값은 아니다.
10. 사용 환산액 필드에 벤더 보고 금액·계약액·청구액을 넣지 않는다. Standard/global/USD 평가 조건이며 batch·priority·
    지역 할증·구독 할인·세금·서버 도구 요금은 반영하지 않는다.

## Alternatives Considered

### A. 공급자 공식 문서로 확인한 모델만 계산한다
- 장점: 모든 단가에 공식 출처가 있다.
- 단점: 자동 검토 등 실제 사용량의 상당 부분이 계속 미확인으로 남는다.
- 탈락 이유: 같은 기준으로 사용량을 비교한다는 지표 목적을 채우지 못한다. 공식 확인 모델은 우선 적용으로 유지한다.

### B. Codeburn CLI나 가격 캐시를 실행 중 읽는다
- 장점: 최신 요금을 자동으로 따른다.
- 단점: 사용자 환경과 캐시 갱신에 따라 같은 판의 결과가 달라진다.
- 탈락 이유: 같은 입력이 같은 금액과 분석 hash를 만들어야 한다.

### C. 현재 요금을 사건 시각에 소급해 유효하다고 표시한다
- 장점: 기존 `EVENT_TIME` 경로를 그대로 쓴다.
- 단점: 과거 가격의 증거를 꾸민다.
- 탈락 이유: 참조 기준과 사건 시각 기준을 구분할 수 없게 된다.

### D. 조회 때 총 토큰에 단가 하나를 곱한다
- 장점: 적재 경로를 바꾸지 않는다.
- 단점: 캐시·출력의 다른 단가를 잃고 적재 hash의 결정성에서 벗어난다.
- 탈락 이유: 성분별 단가가 환산의 전제다.

## Consequences/Tradeoffs

### Positive

- 넓은 모델 범위를 재현 가능한 고정 단가로 계산한다.
- 공식 확인 모델의 단가와 장문 요율, 원천 시각·토큰·모델을 그대로 보존한다.

### Negative

- Codeburn 값과 별칭은 참조 기준이다. 실제 사용 모델·청구액을 증명하지 않는다.
- OpenAI 계열의 캐시 쓰기 단가는 Codeburn 표 값을 따른다. 공급자 과금과 다를 수 있다.
- 5분 기준 환산액은 실제 TTL·청구와 다를 수 있다.
- 새 모델과 요금 변경은 새 가격판과 정규화 판 갱신이 필요하다.

## Acceptance Criteria

- 같은 입력·프로파일은 같은 Decimal 금액과 분석 hash를 만든다.
- Codeburn 카탈로그의 관련 후보가 모두 적용 또는 사유 있는 제외로 분류되고, 독립 Codeburn 산식과 금액이 일치한다.
- 우선 모델의 단가와 271,999·272,000·272,001 입력 경계가 공식 값과 일치한다.
- 미등록 모델·미검증 의미·성분 누락은 null이고, 캐시 생성 0·양수·누락을 각각 검증한다.
- v1~v4의 기존 결과가 바뀌지 않는다.

## Follow-up

- 가격판 갱신 주기와 담당을 정한다(허브 ADR 0008과 같다).
- 저장소에 고정한 Codeburn 가격표의 재배포 조건을 확인한다.
