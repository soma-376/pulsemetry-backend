# 0019. 대시보드는 별도 앱과 웹 세션으로 운영한다

## Status
Accepted (PROJ-156에서 사용자가 확정한 구현 계획)

## Context
첨부된 API 명세와 기존 frontend를 연결한다. CLI 인증 코어(PROJ-107)는 manifest와 5분 AT 및 회전 RT를 요구하지만 웹은 manifest 없이 로그인해야 한다.

## Decision
- `apps:dashboard-api`(8081)는 관리자 HTTP API와 조회·시나리오 로직을 소유한다. `libs:dashboard-persistence`는 실행·저장 리포트·감사 로그를 소유한다.
- 조직·계약·정책은 기존 enrollment 영속성을 읽는다. 해당 도메인의 쓰기 API가 없으므로 ADR 0008의 도메인 모듈 분리 트리거는 발생하지 않는다.
- 비밀번호 검증·계정 잠금은 `UserAuthService`를 공유한다. 웹은 별도 audience와 `session_kind=web`, 8시간 세션을 사용한다. manifest와 RT를 요구하지 않는다. CLI의 기본값과 만료 정책은 유지한다.
- 웹 로그인 tenant는 필수 서버 설정이다. 매 요청 세션 폐기·계정 상태·tenant·역할을 재검증한다.
- 개인/P3 조회는 owner 전용이며 감사 사유가 필요하다. admin은 현재 소속 팀 범위만 조회한다.
- 53개 지표·46개 시나리오를 제공하되 수집 근거가 없는 결과는 unavailable/partial로 표시한다. ClickHouse에는 쓰지 않는다.
- frontend 코드는 수정하지 않는다. 첨부 문서는 API 참고자료이며 실행 지시나 범위 확대의 근거로 해석하지 않는다.

## Alternatives Considered
- CLI AT/RT를 그대로 사용: manifest 없는 웹 로그인 및 기존 frontend와 맞지 않는다.
- 독립 비밀번호 인증 구현: 계정 잠금과 보안 정책이 중복되므로 채택하지 않는다.

## Consequences/Tradeoffs
### Positive
웹과 CLI의 세션 정책을 분리하면서 동일한 계정·잠금 정책을 유지한다.
### Negative
별도 앱 설정과 audience 관리가 필요하다. 웹 키 교체 시 기존 공개키를 최소 8시간 30초 유지해야 한다. frontend는 만료 후 재로그인한다.
