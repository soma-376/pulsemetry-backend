# 0057. 종료된 비밀번호 인증 경로를 제거한다

## Status

Accepted — 사용자의 명시적인 삭제 요청(PROJ-194). ADR 0056의 비밀번호 인증 경로를 410으로 유지하는 결정을 대체한다. OIDC·서비스 토큰·회원 연결·설치 초대 정책은 유지한다.

## Context

비밀번호 인증은 이미 OIDC로 전환됐고, UserAuthController에는 세 경로에서 410을 반환하는 처리만 남아 있다. 이 처리를 API 목록에 포함하면서 지원하는 API와 종료된 API를 함께 읽어야 했다. 현재 프론트와 CLI 소스에는 이 경로를 호출하는 코드가 없다.

## Decision

- UserAuthController의 비밀번호 가입·로그인·CLI 인가 매핑과 전용 오류를 제거한다. 존재하지 않는 경로는 일반 미등록 경로로 처리한다.
- 현재 API 명세·목록에서 해당 경로와 전용 오류 설명을 제거한다. 요청 제한의 일반 인증 경로 정책은 유지하므로 제한에 먼저 걸리면 429·503을 받을 수 있다.
- 요청 제한·오류 인코딩 테스트는 현재 토큰 교환 경로를 사용한다. 종료 응답 전용 테스트는 제거하고, 기존 인증 회귀 테스트에서 매핑 부재를 확인한다.
- 배포 이력인 Flyway 마이그레이션과 초대 응답의 이력 호환 필드는 변경하지 않는다. 설치 요청의 deprecated 호환 필드도 이 변경의 대상이 아니다.

## Alternatives Considered

410 응답만 계속 유지하면 구 호출자에게 종료 사유를 알려줄 수 있지만, 제거를 요청한 경로와 명세를 계속 보유해야 한다.

## Consequences/Tradeoffs

### Positive

지원하는 인증 API만 코드와 API 목록에 남으며, 기능 문서를 읽을 때 종료된 API를 구별할 필요가 없다.

### Negative

구 경로의 호출자는 전용 종료 응답을 더 이상 받지 못한다. 허브의 기존 410 설명은 이전 종료 정책이며, 이번 사용자 요청에 따른 제거 결정이 후속 변경이다.
