# 0062. 저장된 사용량은 토큰 의미가 확인된 행만 재평가하고 나머지는 사유로 남긴다.

## Status

Accepted — 허브 ADR 0008(`current-public-reference-valuation`)의 저장 데이터 재평가 결정을 backend에서 구현한다. [ADR 0020](0020-정규화-계약-2판은-관측을-식별하고-의미-컬럼으로-교체-저장한다.md) §3의 행 교체와 [ADR 0024](0024-조직별-보존-삭제-경계는-RDS-가-진실원이고-분석-INSERT-는-ClickHouse-fence-를-서버에서-다시-검사한다.md)의 보존 경계는 유효하다.

## Context

- 가격판은 적재 시 행에 저장된다([ADR 0060](0060-사용-환산액은-고정된-참조-가격판으로-계산한다.md)). 가격판을 바꿔도 이미 적재된 행은
  조회만으로 다시 계산되지 않는다.
- develop에 배포된 정규화 판 1의 행은 가격이 없다. 그중 Claude Code 2.1.269~2.1.282 행은 지금과 같은 의미 프로파일
  (`claude-code-exclusive-v1`)을 이미 갖고 있지만, Codex 행과 Claude Code 2.1.283 이후 행은 의미 프로파일이 없다.
  의미가 없는 행은 저장된 토큰에 단가만 다시 곱해 고칠 수 없다.
- 원본 아카이브는 영구 보존이 아니다(infra ADR 0013: dev 7일, prod 30일). 원본이 없는 행은 다시 정규화할 수 없다.

## Decision

1. 내부 운영 명령 `repriceStoredUsage`가 고정한 내보내기 파일과 SHA-256을 입력으로 받아 행마다 다음 넷 중 하나로 분류한다.

   | 분류 | 조건 | 처리 |
   |---|---|---|
   | 재평가 | 정규화 판 1·7·8이고 의미 프로파일이 있다 | 가격만 다시 계산해 현재 판으로 교체한다. 단가가 없으면 null |
   | 현재 판 | 이미 현재 판이다 | 쓰지 않는다 |
   | 재정규화 후보 | 의미가 없거나 배포되지 않은 개발 판(2~6)이고 원본 참조가 있다 | 쓰지 않는다. 원본이 있으면 원본 재정규화로만 고친다 |
   | 복구 불가 | 위와 같은 사유에 원본 참조도 없다 | 쓰지 않는다. 사유와 건수만 보고한다 |

   판 1·7·8은 의미 프로파일 ID와 토큰 유도 규칙이 현재 판과 같다는 것을 코드로 확인한 판이다.
2. 의미가 없거나 원본이 없는 행을 추정값으로 채우지 않는다. 이 행들은 대시보드의 환산 미확인 건수로 남는다.
3. 재평가는 가격 단계만 다시 실행한다. 관측 ID·날짜·토큰·모델·소속·수신 시각·원본 참조를 유지하고, 원래 `ingest_seq`에
   현재 판을 붙인 `row_version`으로 교체한다. 바뀌는 열은 `row_version`·`normalizer_rev`·`analysis_hash`·
   `cost_estimated_usd`·`pricing_version` 다섯뿐이다.
4. 적재는 기존 typed sink와 ClickHouse fence, RDS 보존 경계를 그대로 지난다. 수신 ledger·heartbeat·원본 아카이브는 쓰지 않는다.
5. 배치 전체의 트랜잭션은 아니다. 중간에 실패하면 같은 입력으로 다시 실행해 이어서 진행한다. 다시 실행하면
   이미 목표와 같은 행은 건너뛴다. 내보낸 뒤 지워진 행, 보존 경계 밖으로 밀린 행, 더 높은 버전이 적재된 행도 건너뛰고
   건수로 보고한다. 내보낸 값도 목표도 아닌 다른 값으로 바뀐 행이 있으면 오래된 입력으로 덮어쓰지 않고 중단한다.
6. 재정규화 후보의 원본 존재는 원본 참조 목록으로 객체 메타데이터만 조회해 확인한다. 원본 내용을 내려받거나 모델 입력에
   넣지 않는다.
7. **기존 데이터 재처리 완료**는 다음이 모두 충족됐을 때만 판정한다. 재평가 대상이 0건이다. 재정규화 후보마다 원본 존재를
   확인했고, 원본이 있는 행은 재정규화했으며 없는 행은 복구 불가로 사유와 건수를 기록했다. 복구 불가 행을 추정으로 채우지 않았다.

## Alternatives Considered

### A. 모든 기존 행을 원본에서 다시 정규화한다
- 장점: 매핑·의미·가격을 모두 현재 판으로 맞춘다.
- 단점: 원본 보존 기간이 짧아 대부분의 과거 행은 원본이 없다. 재정규화 경로도 아직 없다.
- 탈락 이유: 의미가 이미 확인된 행까지 원본에 묶을 필요가 없다. 원본 재정규화는 의미가 없는 행에만 쓴다.

### B. 의미가 없는 행에 기본 의미를 가정하고 계산한다
- 장점: 미확인 건수가 줄어든다.
- 단점: 캐시·reasoning 포함관계를 꾸며 이중 계산이나 과소 계산이 생긴다.
- 탈락 이유: 미검증 의미는 null이라는 ADR 0020 §4를 어긴다.

### C. ClickHouse 금액 열만 일괄 UPDATE한다
- 장점: 빠르다.
- 단점: 정규화 판·hash·보존 경계·sink fence를 건너뛴다.
- 탈락 이유: 같은 관측의 교체는 `row_version`으로만 한다.

## Consequences/Tradeoffs

### Positive

- 의미가 확인된 과거 행의 환산액을 원천 변경 없이 복구한다.
- 복구할 수 없는 범위를 사유와 건수로 드러낸다.

### Negative

- 원본이 없는 의미 미검증 행은 영구히 환산 미확인으로 남는다.
- 원본 재정규화 경로는 이 명령에 없다. 원본이 남은 재정규화 후보를 처리하려면 별도 작업이 필요하다.

## Acceptance Criteria

- 실제 ClickHouse·RDS 위에서 쓰기 중 실패 → 같은 입력으로 재개 → 재실행 쓰기 0건을 검증한다.
- 재평가 행은 허용한 다섯 열만 바뀌고, 재정규화 후보와 복구 불가 행은 바뀌지 않는다.
- 내보낸 뒤 지워진 행·경계 밖 행·더 새 행은 건너뛰고, 다른 값으로 바뀐 행은 중단한다.

## Follow-up

- 원본 재정규화 경로(ADR 0020 Follow-up의 재처리 기능)를 만든다.
- dev 원본의 실제 보존 설정과 객체 존재를 확인한 뒤 dev 기존 데이터의 재처리 완료를 판정한다.
