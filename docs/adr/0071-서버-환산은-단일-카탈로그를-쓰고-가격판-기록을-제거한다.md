# 0071. 서버 환산은 단일 카탈로그를 쓰고 가격판 기록을 제거한다

## Status

Accepted — 허브 ADR 0028의 backend 구현이다. ADR 0020·0060의 가격판 선택·기록, ADR 0023의 snapshot 가격판 기록, ADR 0061·0063의 가격판 혼재 차단과 ADR 0062의 가격판을 기준으로 한 재평가를 대체한다. 원천 보존·행 교체·토큰 의미·null·보존 경계 규칙은 유지한다.

## Context

서버는 과거 가격 프로파일과 실행 설정을 유지하고 모든 계산 행에 가격판을 적었다. 허브 ADR 0028은 단일 참조 단가표와 저장된 환산액의 합산을 채택했다. 구 이미지와 새 이미지가 교체되는 동안 원본·캐시 스키마는 함께 읽을 수 있어야 한다.

## Decision

1. `PricingStage`는 하나의 참조 카탈로그로 계산한다. 가격판 ID·과거 가격판·사건 시각별 가격 선택·`none` 선택·`PULSEMETRY_PRICING_PROFILE`을 제거한다. 공식 확인 단가 우선, Codeburn 출처와 별칭, 요청별 장문 요율, 토큰 의미와 미보고의 null 규칙은 유지한다.
2. `EventObservation`·분석 해시·typed INSERT에는 가격판 필드가 없다. `normalizer_rev`를 10으로 올리되 `observation_id`와 source identity는 바꾸지 않는다. 계산 결과 금액은 계속 해시 재료다.
3. 기존 nullable `pricing_version` 물리 열은 구 이미지 복구와 기존 체크포인트 호환용으로 남긴다. 새 INSERT는 이 열을 지정하지 않아 NULL로 저장하며 기존 행을 갱신하거나 지우지 않는다. 배포된 DDL 파일은 수정하지 않는다.
4. 대시보드는 저장된 금액을 합산하며 가격판으로 값을 숨기지 않는다. 새 snapshot·응답은 가격판을 기록하지 않는다. 캐시 의미 변경은 조회 계약 번호를 올려 이전 snapshot과 분리한다.
5. 재평가는 명시한 입력과 범위에만 현재 카탈로그를 적용한다. 이전 정규화 규칙 1·7·8·9의 의미가 확인된 행을 지원한다. 구 체크포인트의 가격판은 과거 해시 검증에만 읽는다. 현재 규칙의 행이 현재 계산 결과와 다르면 같은 행 버전으로 덮어쓰지 않고 중단한다. 새 결과는 가격판을 기록하지 않는다.
6. 이 전환만으로 기존 금액을 재평가하지 않는다. 내보내기 해시·tenant·관측·기존 행 검증·fence·재실행 안전성을 유지한다. 갱신한 행의 업무 값 중 변경 가능한 것은 환산액뿐이며 정규화 번호·행 버전·해시를 함께 갱신한다. 구 가격판 호환 열은 새 행에서 NULL이 된다.

## Alternatives Considered

### A. 기존 물리 열을 즉시 삭제한다
- 장점: 스키마에서도 흔적이 사라진다.
- 단점: 구 이미지 복구와 배포 중 공존을 깨뜨린다.
- 탈락 이유: 현재 쓰기·조회·표시 제거에 파괴적 삭제는 필요하지 않다.

### B. 가격판 ID를 상수 하나로 계속 기록한다
- 장점: 적재 구조를 유지한다.
- 단점: 사용하지 않는 가격판 기록과 설정 의미가 남는다.
- 탈락 이유: 버저닝 전체 제거 결정에 맞지 않는다.

## Consequences/Tradeoffs

### Positive

- 하나의 가격표만 유지하고 저장된 금액이 다른 가격판 때문에 사라지지 않는다.
- 기존 금액·원천·구 이미지 복구 경로를 보존한다.

### Negative

- 과거 가격 재현은 당시 코드·배포 이력에 의존한다.
- 호환용 물리 열과 구 체크포인트 해시 판독은 별도로 제거할 때까지 남는다.

## Acceptance Criteria

- 정확한 금액·장문 경계·Codeburn 대조·null 조건 테스트가 유지된다.
- 새 원본 INSERT에 가격판 키가 없고 DB에는 NULL이며 기존 금액은 유지된다.
- 구 체크포인트의 해시 조작을 거부하고 명시 재평가·중단 후 재개·재실행 무쓰기를 검증한다.
- dev 실제 신규 관측을 금액과 함께 수집하고 대시보드에 표시한다.
