# 0078. 세션 집계는 보존하고 계약액 비율은 효력 이력에 근거해 별도로 설계한다.

## Status

Accepted — 세션 API·집계 보존과 후속 카드 구현의 데이터 전제다. 카드와 계약 이력 구현은 포함하지 않는다.

## Context

PROJ-318은 팀 화면의 세션 탭만 제거한다. 세션 집계는 개요·팀 상세·사용자·구성원·제품 응답과 CSV에서 계속 쓰인다. PROJ-317의 자동 누적도 세션 최초 등장과 지표별 결손을 계산한다.

현재 VendorCommands.saveVendor는 tiers의 좌석 수와 좌석별 월 금액을 곱해 monthlySeatFeeUsd를 저장한다. 기존 계약을 PUT하면 저장된 effectiveFrom을 유지한다. vendor_contract_versions는 수정 버전을 남기지만 실제 요금 변경과 입력 정정의 구분은 없다. SettingsValues.summary는 현재 active 계약만 합산하므로 과거 기간의 배분 계약액으로 재사용할 수 없다.

## Decision

세션 원천·snapshot 필드, firstSessionDays·firstSessionBuckets·누적 계산·파생 함수와 공개 DTO를 유지한다. 팀 목록·사용자의 sort=session도 보존한다. 화면 선택 축 제한을 backend 기능 축소로 전파하지 않는다. 이번 탭 정리에는 migration이나 API 필드 변경이 필요하지 않다.

사용 관측은 세션 수·금액 양수 여부로 판정하지 않는다. 팀 미배정 행은 정상 응답의 pricedUsageRows+unpricedUsageRows, 구성원은 periodUsage의 존재로 판단한다. 카운터 부재·조회 실패를 0으로 만들지 않는다. 세션 결손은 정상 비용·토큰 상태에 전파하지 않는다.

구독료 대비 사용 환산액 카드의 제품 정책은 허브 ADR 0032를 따른다. 후속 구현은 기존 수정 버전에서 효력 이력을 추측하지 않고 실제 변경·정정·확인 근거가 있는 별도 효력 모델을 확보한다. 현재 계약 월 합계 API는 의미를 바꾸지 않는다.

후속 계산은 snapshot의 조직·제품·기간·asOf와 계약 근거 버전을 함께 고정한다. dashboard는 읽기와 자기 snapshot/cache 쓰기를 맡고 계약 이력 명령·정합성은 enrollment가 소유한다. 현재 보관·만료 상태로 과거 유효 계약을 제외하지 않는다. 기존 recorded_at을 effectiveFrom으로 이관하지 않는다.

KST 달력 월·효력 경계별로 구매 좌석 월 총액을 실제 월 일수로 일할 배분하고 진행일은 asOf까지의 경과 시간 비율을 사용한다. 중간 나눗셈을 반올림하지 않는다. 누락·중복·효력 불명 구간과 0 분모는 null 사유로 유지한다. 사용량과 계약액을 다른 snapshot에서 섞지 않는다.

후속 명세에 데이터 필드·버전/효력 선택·정정·산식·직렬화 정밀도·상태·예제를 기록한다. 실제 subscriptionUsageValue API·카드·계약 이력 migration은 별도 구현 티켓에서 추가한다.

## Alternatives Considered

### A. 세션 전용 SQL과 API를 제거한다
- 장점: 팀 탭과 backend 축이 같아진다.
- 단점: 다른 소비자의 세션 계약이 깨진다.
- 탈락 이유: 공개 세션 기능 유지가 명시 범위다.

### B. 현재 active 계약과 recorded_at으로 과거를 복원한다
- 장점: 기존 테이블만 사용한다.
- 단점: 변경 효력·정정·과거 계약 공백을 구별할 수 없다.
- 탈락 이유: 과거 분모를 확인된 값으로 보장하지 못한다.

## Consequences/Tradeoffs

### Positive
- 세션 탭 제거와 API·데이터 보존을 별도로 검증한다.
- 계약 이력 불확실성을 비율 0이나 정상값으로 숨기지 않는다.

### Negative
- 사용하지 않는 탭의 세션 집계도 기존 API 소비자를 위해 계속 관리한다.
- 후속 카드에는 효력·정정 입력과 snapshot 근거 보완이 필요하다.

## Follow-up

- [후속 계약 이력 및 subscriptionUsageValue 설계](../subscription-usage-value-design.md)에 원천 근거·정확 분수 계산·snapshot·상태별 구현 인수 기준을 기록한다. API나 DB 변경은 별도 티켓으로 수행한다.

## Acceptance Criteria

- 세션 정렬·누적·파생값과 세션/금액 결손 사용의 행 수·마지막 사용을 기존 dashboard 회귀로 확인한다.
- 계약액 일할 계산의 월중 변경·월 경계·윤년·asOf·0·누락 사례가 명세에서 재현된다.
