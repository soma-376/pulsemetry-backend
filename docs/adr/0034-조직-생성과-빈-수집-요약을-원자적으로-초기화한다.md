# 0034. 조직 생성과 빈 수집 요약을 원자적으로 초기화한다

## Status

Accepted — ADR 0033의 B 수집 요약 미생성을 대체하고 ADR 0021의 초기 상태를 보완한다. 기존 이력 부재·백필·live/replay 갱신 규칙과 운영 수신 기록 활성화 조건은 유지한다.

## Context

조직과 오너만 있는 신규 조직은 정상적인 빈 대시보드를 조회할 수 있어야 한다. 기존 조회 계층은 요약과 백필 완료 기록이 모두 없으면 과거 이력을 알 수 없어 503을 반환한다. 시드에서 빈 요약을 생략하자 신규 조직도 이 조건에 걸렸다.

현재 운영용 조직 생성 API는 없고 SQL·시드·JPA가 조직을 생성할 수 있다. 특정 생성 서비스에만 초기화를 넣으면 우회 경로가 남는다.

## Decision

- `telemetry_ops`의 다음 Flyway 마이그레이션 V3가 `enrollment.tenants`의 AFTER INSERT 트리거와 초기화 함수를 설치한다. `enrollment` 마이그레이션이 먼저 끝나야 한다. 앱 조립에서 이 순서를 명시한다.
- 조직 INSERT와 같은 트랜잭션에서 `tenant_ingest_summary`를 생성한다. 수신·관측 시각은 NULL, `has_pre_ledger_history=false`다. 이는 예시 데이터가 아닌 신규 조직의 필수 초기 상태다. 요약 생성이 실패하면 조직 INSERT도 실패한다.
- 동일 UUID의 요약이 이미 있으면 `ON CONFLICT DO NOTHING`으로 보존한다. 조직 UPDATE와 반복 기동은 요약을 초기화하지 않는다.
- 트리거 함수는 마이그레이션 소유자 권한으로 실행하고 search_path를 pg_catalog로 고정한다. 대상 테이블을 스키마로 한정하여 조직 생성 계정에 운영 요약의 직접 쓰기 권한을 추가하지 않는다.
- 기존 조직에 없는 요약을 마이그레이션이나 조회 시 일괄 생성하지 않는다. 과거 이력을 빈 상태로 오인할 수 있으므로 기존 복구·백필 절차를 따른다. 기존 B에도 자동으로 빈 이력을 소급 선언하지 않는다.
- 대시보드 원천 조회는 읽기 전용이며 빈 상태를 쓰지 않는다. 신규 조직은 생성된 요약을 읽어 `200`, `meta.dataState=never_observed`, `ingest.status=empty`를 반환한다. 이력 판정 근거가 없는 기존 조직은 계속 503이다.
- 시드 B는 조직·오너만 명시적으로 넣고 빈 요약은 트리거가 생성한다. A/C의 합성 수집 요약은 같은 시드 적재 트랜잭션에서 자동 생성된 빈 행을 갱신한다. 팀·계약·벤더·설정 같은 예시 데이터는 B에 추가하지 않는다.

## Alternatives Considered

JPA 콜백이나 서비스 초기화는 직접 SQL·시드를 놓친다. 조회 시 upsert는 읽기 전용 권한을 깨뜨리고 과거 이력 누락을 숨긴다. 모든 기존 조직에 빈 행을 채우면 보존 삭제된 이력이 없는 것으로 바뀔 수 있다.

## Consequences/Tradeoffs

### Positive

조직 생성 경로와 무관하게 빈 상태를 원자적으로 보장한다. 첫 실제 수신은 기존 MIN/MAX upsert로 빈 시각을 채운다.

### Negative

telemetry_ops 마이그레이션은 enrollment.tenants 존재를 요구한다. 조직 생성은 요약 저장소와 결합되며 해당 테이블의 장애도 조직 생성 실패가 된다. 트리거 도입 전 요약이 누락된 조직은 별도 이력 확인이 필요하다.

## Acceptance Criteria

직접 SQL 및 JPA 조직 생성, rollback, 요약 쓰기 실패, 기존 요약 보존, 기존 조직 미백필, 최초 실제 수신, B 시드 최소 데이터, 신규 조직 200 빈 응답과 기존 이력 누락 503을 검증한다.
