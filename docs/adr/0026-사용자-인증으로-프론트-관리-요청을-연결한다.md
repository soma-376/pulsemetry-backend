# 0026. 사용자 인증으로 프론트 관리 요청을 연결한다

## Status
Accepted — ADR 0022의 인증 포트에 실제 사용자 인증 어댑터를 연결한다. 대시보드 원천 DB는 계속 읽기 전용이다. 부분 대체: [ADR 0037](0037-메일은-outbox에-적재하고-enrollment-api의-발송-작업이-SMTP로-보낸다.md)이 "초대는 코드 발급이며 이메일 발송 완료나 queued로 표시하지 않는다"를 대체한다. [ADR 0048](0048-좌석-원장은-벤더-계정별-배정-이력이고-연결된-등록-제품에서는-커넥터-동기화가-권위를-갖는다.md)과 [ADR 0049](0049-좌석-회수와-복원은-미리보기에-묶어-실행하고-벤더-제어가-없으면-관리자-조치-확인으로-끝난다.md)가 "벤더 좌석 제어는 구현하지 않는다"를 대체한다(벤더 연결·좌석 원장, 회수·복원은 커넥터가 구현한 만큼 벤더 제어이고 나머지는 관리자 조치 확인). 나머지 결정은 유효하다.

## Context
사용자가 SSO 없이 프론트 화면 기준으로 구현하도록 승인했다. 조회 API와 별개로 팀 배정·초대 코드·수동 계약 저장이 필요하다.
미병합 PROJ-107의 사용자 인증 구현을 기존 Git 이력에서 재사용한다.

## Decision
enrollment-api가 이메일·비밀번호 로그인과 관리 명령 HTTP를 제공한다. dashboard-api는 공개키와 계정·세션 조회로 AT를 검증한다.
두 앱은 허용된 브라우저 origin에 CORS를 설정하며, 브라우저가 각 Spring API에 직접 요청한다.
대시보드와 관리 명령은 owner/admin만 허용한다. 새 사용자 역할은 기존 member/admin 범위다.
팀 배정은 서버 시점의 소속 이력을 추가하고 과거 팩트를 바꾸지 않는다.
초대는 코드 발급이며 이메일 발송 완료나 queued로 표시하지 않는다.
수동 계약은 벤더 종류·플랜·등급별 좌석·월 단가·효력 날짜와 버전 이력으로 저장한다.
기존 기간 약정·토큰 할인 계약을 좌석 계약으로 환산하지 않는다. 실제 청구액·벤더 좌석 제어는 구현하지 않는다.
POST 명령은 조직·사용자·경로·본문에 묶은 24시간 멱등성을 제공한다. 초대 코드가 포함된 재시도 응답은 별도 256비트 키로 AES-GCM 암호화하여 저장한다.
관리 HTTP는 기존 enrollment 앱에 추가하며 영속성 연산과 새 DDL은 enrollment-persistence가 소유한다.

## Alternatives Considered
조회 앱에 원천 쓰기 계정을 주거나 프론트 서버 프록시를 두는 방식은 선택하지 않는다.

## Consequences
### Positive
검증된 사용자에서 조직을 식별하고 프론트 폼의 변경을 실제 DB에 보존한다.
### Negative
브라우저는 조회와 관리 API의 base URL을 구분해야 한다. 별도 멱등 응답 암호화 키를 보관해야 한다.
