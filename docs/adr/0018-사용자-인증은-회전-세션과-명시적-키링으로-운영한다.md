# 0018. 사용자 인증은 회전 세션과 명시적 키링으로 운영한다

## Status
Accepted — PROJ-107 구현 계획에서 승인한 서버 내부 결정.

## Context
ADR 0007은 자체 인증을 선택했지만 회전·잠금·키 교체의 기준은 남겨 두었다.
사용자 세션은 설치 자격증명과 수명이 다르며, 여러 인스턴스가 같은 RT를 동시에 소비할 수 있다.

## Decision
- 코어는 `:libs:security`, SQL은 `:libs:enrollment-persistence`, HTTP와 빈 조립은 enrollment-api가 소유한다.
- AT는 RS256, 5분, 허용 시계 오차 30초다. issuer·audience·kid를 명시하며 개인키는 읽기 전용 PKCS8 PEM 파일로 주입한다.
- RT는 256비트 난수이며 SHA-256 해시만 저장한다. 세션 절대 수명은 30일이다.
- 세션 행 잠금 아래 RT를 회전한다. 사용된 RT 재사용은 해당 세션 전체를 폐기한다. 거부를 반환하기 전에 폐기를 커밋한다.
- 일반 갱신은 세션 revision을 보존한다. 상태·role은 DB에서 다시 읽는다. 폐기 세션·정지된 tenant/member는 사용자 AT 검증에서도 거부한다.
- 비밀번호는 bcrypt cost 12, 최소 12 Unicode 코드포인트·최대 UTF-8 72바이트다. 잘라서 해싱하지 않는다.
- 계정은 15분 실패 구간 내 5회 실패 후 15분 잠근다. 인증 API의 IP 제한은 분당 30회이며 PostgreSQL에서 원자적으로 누적한다.
- IP는 서블릿 remoteAddr를 사용한다. 임의 X-Forwarded-For를 신뢰하지 않는다. 프록시 복원은 별도 신뢰 설정 없이는 켜지 않는다.
- 서명키는 공개키 선배포 → active kid 전환 → 330초 이상 대기 → 구 공개키 제거 순으로 교체한다.
- 새 API만 명시적으로 연다. 기존 enrollment·관리자 인증과 OTLP ptt_ 검증은 유지한다.

## Alternatives Considered
- 메모리 RT·rate limit: 재시작·다중 인스턴스에서 효력이 갈려 배제한다.
- 재사용 RT 허용 구간: 동시 요청의 편의 대신 유출 탐지를 약화하므로 두지 않는다.

## Consequences/Tradeoffs
### Positive
DB 트랜잭션과 테스트로 회전·잠금의 근거를 확인할 수 있다.
### Negative
정상 동시 갱신도 세션을 폐기하므로 클라이언트가 갱신을 직렬화해야 한다.
IP 제한은 같은 NAT 사용자가 공유하며, 프록시 주소를 그대로 받는 배포에서는 프록시 단위 제한이 된다.
키 교체는 모든 검증 인스턴스의 공개키 배포를 먼저 완료해야 한다.

## Acceptance Criteria
가입·JWT 검증·RT 재사용·잠금·키 교체 테스트와 기존 enrollment/OTLP 회귀가 통과한다.
