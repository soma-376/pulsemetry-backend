# 0027. local 프로필에서 개발 시드를 초기화한다

## Status
Accepted — ADR 0025의 수동 실행 전용·서버 의존 제외 결정을 대체한다. 로컬 DB 제한, 명시적 초기화, 스키마 소유권은 유지한다.
ClickHouse 스키마 사전 준비 요구는 [ADR 0028](0028-local-시드-전에-기존-클릭하우스-마이그레이션을-실행한다.md)이 부분 대체한다.
Spring 기동 없이 개발 Compose에서 준비하는 경로는 [ADR 0030](0030-개발-Compose가-스키마와-시드를-준비한다.md)이 추가한다.

현재 실행 경로는 [ADR 0031](0031-개발-시드는-Docker에서만-실행한다.md)이 부분 대체한다. 서버 자동 실행·공유 코어·호스트 수동 시드는 제거하며, 로컬 제한·완료 데이터 보존·스키마 소유권은 유지한다.

## Context
사용자가 기존 local 프로필에서 기본 설치 데이터와 대시보드 A/B/C 데이터를 서버 기동 시 준비하도록 요청했다.
기존 LocalSeeder가 첫 조직을 선택하면 대시보드 시드 조직에 설치 데이터가 섞인다.

## Decision
순수 Kotlin `:libs:dev-seed-core`에 생성·적재·검증을 둔다. Spring 빈과 runner는 enrollment-api가 조립한다.
수동 Gradle 명령은 `:tools:dev-seed`에 유지하고 같은 라이브러리를 호출한다.
`local` 프로필과 `pulsemetry.local-seed.enabled=true`를 모두 만족할 때만 자동 실행한다.
local 설정은 enabled 기본값을 true로 제공하고 환경변수로 끌 수 있다. 다른 프로필은 기본 비활성이다.
앱의 JDBC 주소가 고정 로컬 DB인지 확인한 뒤 고정 ID의 기본 개발 조직을 준비하고 A/B/C를 실행한다.
자동 실행은 ready 기록과 조직 식별자가 유효하면 기준일·내용을 다시 비교하지 않고 건너뛴다.
미완료 적재는 기동 실패로 드러내며 자동 삭제·복구하지 않는다. 엄격한 내용 비교는 seedVerify가 맡는다.
기준일 미지정 시 최초 적재일(서울)을 사용하며 재기동 때 자동으로 날짜를 갱신하지 않는다.
업무 스키마가 없으면 소유 앱의 마이그레이션을 먼저 적용해야 한다. 시더가 업무 DDL을 소유하지 않는다.

## Alternatives Considered
서버가 tools 모듈에 의존하거나 생성 로직을 복사하는 방법은 실행 진입점과 재사용 로직을 섞는다.
매 기동 시 원래 시드와 비교하는 방법은 개발 중 변경한 데이터 때문에 서버를 띄울 수 없게 한다.

## Consequences
### Positive
기존 local 사용 방식과 수동 명령을 유지하며 재기동으로 개발 데이터를 덮어쓰지 않는다.
### Negative
서버 클래스패스에 개발용 라이브러리가 포함된다. 실행은 프로필·설정·로컬 주소 검사로 제한한다.
local 시드가 켜진 기동은 Docker 및 두 DB의 스키마 준비에 의존한다.
기존 임의 ID의 로컬 조직은 삭제하지 않으며 새 고정 개발 조직과 공존할 수 있다.
