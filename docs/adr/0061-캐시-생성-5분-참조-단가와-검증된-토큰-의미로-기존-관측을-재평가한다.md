# 0061. 캐시 생성 5분 참조 단가와 검증된 토큰 의미로 기존 관측을 재평가한다.

## Status

Accepted — ADR 0060의 캐시 생성 양수 TTL 미확인 시 null 정책과 기존 검증 행의 재처리 보류, ADR 0020 §7의 의미 프로파일이 다르면 무조건 합산하지 않는 결정을 부분 대체한다. 원천·관측 식별·행 교체·보존 경계와 기존 가격표 불변성은 유효하다.

기본 가격판은 [ADR 0062](0062-공개-단가가-확인된-Luna-모델을-불변-가격판에-추가한다.md)에서 v4로 개정한다. 이 문서의 v3 정의와 기존 평가 결과는 보존한다.

Desktop 두 버전의 확인된 완료 분기는 [ADR 0064](0064-확인된-Desktop-완료-분기만-사용량-프로파일에-추가한다.md)로 추가한다. 다른 Desktop 범위는 검증 완료로 확장하지 않는다.

## Context

허브 ADR 0009는 Claude 캐시 생성 5분 공시 단가를 현재 참조 평가의 기준으로 정하고, 검증된 Codex 토큰 의미를 연결하며, 승인된 기존 관측의 재평가를 허용한다. 가격을 처음 연결하기 전 적재한 행은 조회만으로 재계산되지 않으므로 가격 단계와 기존 관측의 재처리를 함께 연결해야 한다.

## Decision

1. `CurrentPublicPrices`에 불변 `public-standard-global-reference-2026-10-16-v3` 프로파일을 추가하고 `RowVersioning.NORMALIZER_REV`를 6으로 올린다. v1/v2 선택과 단가·기준 시각·정책은 그대로 유지한다. 새 기본값은 v3다.
2. v3의 Claude cache-create 단가는 정확한 모델의 공식 5분 단가다. 프로파일의 `cacheCreateReferenceTtlSeconds=300`은 `CURRENT_REFERENCE` 평가 기준이며 실제 TTL 판정이 아니다. 명시 0은 0, 알려진 양수는 해당 단가로 계산하고 미보고는 null이다. 이전 프로파일의 null 규칙은 바꾸지 않는다.
3. Codex 토큰 의미 `codex-responses-inclusive-v1`은 input이 cache read/write를 포함하고 output이 reasoning을 포함한다. `input_uncached = input - cache_read - cache_create`이며 `total = input + output`이다. emitter의 `tool_token_count`는 total의 별도 보고이므로 더하지 않는다. 버전·이벤트별 원천 구현과 fixture가 증명하는 범위에 한정하며, cache-write 키 미보고는 null을 유지한다. fixture 이름이나 모델명으로 미검증 의미를 우회하지 않는다. 가격표에는 정확한 지원 모델과 검증된 의미 프로파일만 연결한다. provider가 보고되지 않은 사실은 그대로 두며 평가 기준으로 원천 provider를 덮어쓰지 않는다.
4. 기존 관측의 재평가는 원래 마스킹된 아카이브와 신원·시각 문맥으로 Adapter부터 수행하고 기존 Enricher·분석 sink를 지난다. `observation_id`는 유지하며 `row_version = (normalizer_rev << 32) | ingest_seq`에 따라 rev6이 이전 판을 교체한다. `analysis_hash`는 새 의미·금액을 반영하고, 원본 아카이브는 덮어쓰지 않는다.
5. 운영 재처리는 원래 receipt·수신 시각을 유지하며 새로운 live 수신으로 ledger·신선도·heartbeat를 갱신하지 않는다. 보존 삭제 경계와 sink fence를 우회하지 않는다. E2E의 live 입력 재전송을 사용하는 경우에는 archive·수신 영수증이 추가되는 별도 실행임을 표시하고 원래 아카이브와 신원·시각·관측 집합의 보존을 대조한다.
6. 실행 범위·입력 파일·코드 및 프로파일 판·전후 분석 행을 고정해 증거를 남긴다. 이번 범위는 main 검증 조직의 기존 primary 사용량 전체이며 이전 v1 가격 행도 포함한다. 타 baseline 조직의 기존 관측은 보존한다. 독립 Decimal 산식에서 금액을 계산하고 API 반환값을 기대값으로 복사하지 않는다. 동일 입력 재처리와 역순 재전송 뒤 최신 관측 수가 늘지 않는지 확인한다.
7. 재평가 결과는 새 snapshot에서 읽는다. 10월 1–7일의 일별·팀별 누적 금액을 독립 기대값으로 검증하며, 미가격 관측이 남는다면 사유와 영향을 명시한다. 저장된 행을 직접 UPDATE하거나 dashboard에서 가격을 덧씌우지 않는다.
8. Dashboard는 `claude-code-exclusive-v1`·`codex-responses-inclusive-v1`의 canonical 비중복 성분 합산을 허용한다. `semantics_profile`의 수만으로 차단하지 않고 명시적인 호환 집합과 미검증·누락 행 수를 확인한다. 다른 프로파일이나 미검증 행을 자동 호환으로 취급하지 않는다. `pricing_version` 혼재 차단은 그대로 유지하며 main의 전체 범위 재평가로 새 v3를 맞춘다.
9. 모델별 선택 규칙으로 단일 요청 input이 272,000을 **초과**할 때 `gpt-6-astra`의 입력·cache 단가에 2, output 단가에 1.5를 곱한다. 경계의 동일값은 기본 단가다. 다른 모델과 v1/v2에 이 규칙을 기본 적용하지 않는다. 단일 응답 사용량으로 확인된 이벤트만 입력 길이의 근거로 쓰며 여러 요청의 누계에 적용하지 않는다.

### Codex 근거와 적용 범위

- 기존 정확 버전 0.153.4·0.154.0-alpha.6.2·0.155.0-alpha.2.6·0.155.0-alpha.9.2의 `ResponseCompletedUsage` 변환과 `sse_event_completed` emitter를 근거로 지원 이벤트에만 의미를 연결한다.
- 0.162.0-alpha.17.2는 기존 제한된 `response.completed` 캡처와 emitter 일치 근거의 범위를 유지한다. 공개된 exact 태그의 소스를 확인한 것으로 주장하거나 다른 로그에 확장하지 않는다.
- producer가 보고한 0은 보고값이다. upstream의 실제 측정 0과 내부 default 0을 구분했다는 의미는 아니다. 키가 없는 값을 backend가 0으로 만드는 정책과 구분한다.
- 원천 구현은 `codex-rs/codex-api/src/sse/responses.rs`의 `From<ResponseCompletedUsage>`와 `codex-rs/otel/src/events/session_telemetry.rs`의 `sse_event_completed`다. 정확 commit·fixture 대응은 `PROFILE-EVIDENCE.md`에서 관리한다.

## Alternatives Considered

### 기존 221행을 영구 보존하고 파생 입력만 늘린다

최초 검증 증거 보존에는 유효했지만 승인된 기존 데이터 재평가와 실제 사용 기간의 화면 확인을 충족하지 못한다. 과거 산출물을 별도로 보존하고 최신 분석 판을 갱신한다.

### v2의 정책과 단가를 바꾼다

같은 `pricing_version`으로 다른 결과가 나오므로 채택하지 않는다.

### ClickHouse 금액 열만 일괄 수정한다

정규화 판·hash·관측별 검증·sink 경계를 건너뛰므로 채택하지 않는다.

## Consequences/Tradeoffs

### Positive

- 최신 평가 기준을 과거 관측에도 일관되게 적용한다.
- 기존 가격 버전과 원본 증거를 보존하면서 계산 경로를 재현한다.

### Negative

- 재처리 범위를 벗어난 행은 이전 평가 판을 유지하므로 가격 판 혼재를 확인해야 한다.
- 실청구와 5분 표준 평가의 차이는 계속 존재한다.
- 미검증 Codex 범위와 누락 성분은 새 가격표만으로 복구되지 않는다.

## Follow-up

- Codex의 지원 버전·이벤트별 포함관계 근거와 검증 결과를 `PROFILE-EVIDENCE.md` 및 가격 근거 문서에 연결한다. 근거가 확인되기 전에는 지원 범위를 확대하지 않는다.
- 재평가 실행의 전후 대조·미가격 사유·10월 1–7일 API 및 화면 검증을 별도 실행 보고서에 기록한다.
