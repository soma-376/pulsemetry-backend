# 0059. 기본 개발 시드는 A/B로 두고 C는 명시해서 생성한다

## Status

Accepted — ADR 0032의 A/B/C를 기본 시드로 제공하는 결정을 부분 대체한다. 온보딩 완료 저장, Docker 전용 실행, 완료된 데이터 보존과 인증 계약은 유지한다.

## Context

사용자가 예외 데이터 회사 C를 기본 개발 환경에서 빼고 신규 조직 B는 유지하도록 요청했다.
현재 Compose와 수동 시드 명령은 시나리오를 생략하면 A/B/C를 선택하므로, C를 지워도 다음 초기화에서 다시 만들어진다.
C의 누락 비용·미매핑 관측 사례는 회귀 검증에 필요하다. 변경 범위는 이 저장소의 개발 시드 선택과 운영 절차다.

## Decision

- Compose와 `init`, `plan`, `apply`, `verify`, `reset`의 시나리오 생략 시 기본 선택은 A/B다. 환경변수와 명시한 명령 인자가 있으면 그 선택을 따른다.
- C 생성기와 예외 데이터 검증은 유지한다. C가 필요한 격리 회귀 검증은 `C` 또는 `A,B,C`를 명시한다. D/E도 명시할 때만 선택한다.
- 기본 선택의 변경은 이미 적재된 조직을 삭제하거나 갱신하지 않는다. 기존 C 삭제는 사용자가 C 삭제를 명시적으로 요청한 경우 `reset C`로 수행하고, 다음 초기화 설정에서도 C를 제외한다.
- C 삭제는 C의 UUID로 한정한다. B와 다른 회사의 데이터·OIDC 연결·세션은 보존한다. A의 기준일 변경과 재적재는 C 삭제와 별도의 명시적 관리 작업이다.
- A/B의 회사별 OIDC 설정, 회원 최초 SSO 연결, JWT·세션 계약은 바꾸지 않는다. C는 선택형 데이터 시나리오이며 기본 Cognito 로그인 대상에 추가하지 않는다.

## Alternatives Considered

C 생성기까지 제거하면 예외 데이터 회귀 검증을 잃는다. Compose에서만 C를 빼면 시나리오를 생략한 수동 명령이 다시 C를 선택하므로 기본값을 함께 바꾼다.

## Consequences/Tradeoffs

### Positive

- 일상 개발에서는 정상 사용 A와 신규 조직 B를 제공하고, C는 필요한 검증에서만 만든다.
- 기존 데이터 보존과 회사별 삭제 경계는 유지한다.

### Negative

- 기존 A/B/C 회귀 검증은 C를 명시적으로 준비해야 한다.
- 기존 `.env`나 셸에 A/B/C 선택이 남아 있으면 C가 다시 생성되므로 환경변수도 함께 확인해야 한다.
