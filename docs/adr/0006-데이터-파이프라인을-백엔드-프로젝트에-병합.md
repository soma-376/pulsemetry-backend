# 0006. 데이터 파이프라인을 백엔드 프로젝트에 병합한다.

## Status
Superseded by [허브 ADR 0004](../../../docs/adr/0004-telemetry-pipeline-repo-merge.md) — 이 파일이 제안했던 전체 병합은 **채택됐다.** 결정 원문은 허브 ADR 0004(병합)와 [0005](../../../docs/adr/0005-single-app-telemetry-topology.md)(토폴로지)가 소유하며, 이 파일은 링크 stub 이다.

## Context

이 결정은 두 레포 이상(`ai-telemetry-pipeline` · `pulsemetry-backend` · `infra`)의 코드·계약에 걸려
템플릿 작성 규칙에 따라 **문서 허브로 이관됐다**(PROJ-79). 이 파일은 다른 ADR(0008 등)의 역참조가
끊기지 않도록 번호를 지키는 **링크 stub** 이다.

병합 제안의 배경·대안·결과 분석 원문은
[허브 ADR 0004 — 텔레메트리 파이프라인을 backend 레포로 병합한다](../../../docs/adr/0004-telemetry-pipeline-repo-merge.md)와
이 파일의 git 이력(`git log --follow`)에 있다.

**대체됨(허브 ADR 0004)** — 이 제안은 [허브 ADR 0003](../../../docs/adr/0003-telemetry-pipeline-repo-boundary.md)
에서 한 번 기각됐다가 0004 로 다시 채택됐다. 그 사이의 서술(레포 2개 체제 유지 · collector 만 이관)은
더 이상 유효하지 않다.

## Decision

허브 ADR 0004 가 소유한다 — 전체 병합 채택, ClickHouse 스키마 소유권 이동.
RDB(enrollment) 스키마 소유권은 병합과 무관하게 [ADR 0009](0009-enrollment-스키마-native-enum-채택.md) 가 확정했다.

배포 단위와 계층 배치는 [허브 ADR 0005](../../../docs/adr/0005-single-app-telemetry-topology.md) 가
정한다 — 단일 앱, Collector 바이너리 미사용, 단계는 `:libs:` 모듈.
Collector 를 쓰지 않으므로 수집·마스킹도 이 저장소가 구현하고, 인증 계층은
`:libs:security` 다([ADR 0007](0007-인증-계층으로-spring-security-사용.md)).
구성은 [모듈 지도](../module-map.md)가 담는다.

## Follow-up
- **완료** — 문서 허브 이관(PROJ-79). 본문은 [허브 ADR 0004](../../../docs/adr/0004-telemetry-pipeline-repo-merge.md) 참조.
- **완료** — 병합 재채택으로 배포 단위와 모듈 구성이 확정됐다. 목록은 [모듈 지도](../module-map.md)가 담는다.
- ClickHouse 스키마 소유권이 이 저장소로 오지만 Flyway 는 ClickHouse 를 다루지 않는다.
  DDL 의 진실원과 적용 경로를 함께 정해야 한다(허브 ADR 0004 Follow-up).
