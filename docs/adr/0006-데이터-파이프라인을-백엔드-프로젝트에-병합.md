# 0006. 데이터 파이프라인을 백엔드 프로젝트에 병합한다.

## Status
Rejected — 파이프라인 전체 병합은 채택하지 않는다. 실제 방향은 collector 만 이 저장소로 가져와 인증 계층을 심는 것이며([ADR 0007](0007-인증-계층으로-spring-security-사용.md)), 나머지 앱은 `ai-telemetry-pipeline` 에 남는다. RDB(enrollment) 스키마 소유권은 병합과 무관하게 [ADR 0009](0009-enrollment-스키마-native-enum-채택.md) 가 이 저장소의 Flyway 로 확정했고, ClickHouse 스키마 소유권은 파이프라인에 남는다. 전체 이관은 Python·Kotlin 성능 비교 목적의 재논의 여지만 남긴다. **결정 원문은 [허브 ADR 0003](../../../docs/adr/0003-telemetry-pipeline-repo-boundary.md) 이 소유한다.**

## Context

이 결정은 두 레포 이상(`ai-telemetry-pipeline` · `pulsemetry-backend` · `infra`)의 코드·계약에 걸려
템플릿 작성 규칙에 따라 **문서 허브로 이관됐다**(PROJ-79). 이 파일은 다른 ADR(0008 등)의 역참조가
끊기지 않도록 번호를 지키는 **링크 stub** 이다.

병합 제안의 배경·대안·결과 분석 원문은
[허브 ADR 0003 — 텔레메트리 파이프라인은 별도 레포로 유지하고 collector 만 backend 로 이관한다](../../../docs/adr/0003-telemetry-pipeline-repo-boundary.md)와
이 파일의 git 이력(`git log --follow`)에 있다.

## Decision

허브 ADR 0003 이 소유한다 — 전체 병합 기각, 레포 2개 체제·Python 구현 유지, collector 만 이관.

## Follow-up
- **완료** — 문서 허브 이관(PROJ-79). 본문은 [허브 ADR 0003](../../../docs/adr/0003-telemetry-pipeline-repo-boundary.md) 참조.
- collector 이관으로 새로 생기는 배포 단위는 `:apps:telemetry-ingest` 하나이며,
  collector config 의 소유권이 함께 이동한다.
- ClickHouse 스키마 소유권은 `ai-telemetry-pipeline` 에 남는다.
