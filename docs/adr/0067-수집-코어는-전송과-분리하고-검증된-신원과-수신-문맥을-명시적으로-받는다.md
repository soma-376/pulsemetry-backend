# 0067. 수집 코어는 전송과 분리하고 검증된 신원과 수신 문맥을 명시적으로 받는다.

## Status

Accepted — [ADR 0016](0016-조립-앱은-인증-체인과-단계-호출을-배선하고-스키마-적용-실패를-견딘다.md)의 신원 seam 결정
("수집 모듈에 값만 받는 seam(`IdentitySource`)을 두고 조립 앱이 `SecurityContextHolder` 에서 꺼내 넘긴다")을 대체한다.
스탬프 규칙과 그 위치(마스킹 뒤·아카이브 앞)를 포함한 ADR 0016 의 나머지 결정은 유효하다.

## Context

- `OtlpIngestHandler` 가 HTTP 검사(메서드·경로·Content-Type)와 압축 해제·디코딩·마스킹·스탬프·아카이브·영수증 생성을 한 함수에서 한다.
  receipt ID 는 요청마다 새 UUID, 수신 시각은 진입 시각이다.
- 신원은 `IdentitySource` 가 Servlet 스레드의 `SecurityContextHolder` 에서 꺼낸다. 인증하지 않은 호출자는 `null` 이라 스탬프 없이 지나간다.
- [ADR 0066](0066-OTLP-수신은-Gateway가-JWT만-검증해-Kafka에-접수하고-ingest가-RDB로-다시-검증한다.md)의 Consumer 는 같은 처리를 HTTP 없이 해야 하고,
  재시도마다 같은 receipt ID·수신 시각(message ID·접수 시각)을 써야 row version·ledger 키가 흔들리지 않는다.
- Gateway 는 OTLP 응답 본문·경로·media type 을 ingest 와 같게 내야 하지만, 수집 모듈은 S3 SDK 를 끌고 온다.
- 결정하지 않으면 Consumer 가 가짜 HTTP 요청을 만들거나 `SecurityContextHolder` 를 채우는 우회가 생긴다 — 둘 다 상태 코드를 처리 결과로 해석하게 만든다.

## Decision

1. **전송 독립 코어**: `:libs:telemetry-collector` 의 `OtlpProcessor.process(RawOtlpPayload, VerifiedIngestContext)` 가
   압축 해제 → 디코딩 → 빈 요청 단축 → 마스킹 → 스탬프 → 아카이브 → 다음 단계를 한다.
   - `VerifiedIngestContext` 는 receipt ID·수신 시각·**필수인** `AuthorizedTelemetryIdentity`(tenant·installation) 다.
     검증 전 문맥(Gateway 의 `GatewayAuthContext`)을 그대로 넣지 않는다.
   - 실패는 둘이다. `PermanentIngestException`(디코딩·압축 해제·마스킹·기존 영구 실패)과 그 밖의 예외(일시). HTTP 상태도 Kafka 타입도 모른다.
   - 마스킹 실패도 영구다. HTTP 에서는 지금까지 컨테이너 500 이던 것이 400 이 된다(같은 입력은 다시 보내도 같다).
2. **HTTP 어댑터** `OtlpIngestHandler.handle(request, identity)` 는 메서드·경로·Content-Type 검사와 응답 변환만 한다.
   receipt ID 는 새 UUID, 수신 시각은 진입 시각 — 지금과 같다. `OtlpController` 가 인증된 principal 을 **명시적으로** 넘긴다.
   `IdentitySource`·`SecurityContextIdentitySource` 를 없앤다.
3. **Kafka 어댑터**는 ingest 앱의 `ProcessTelemetry` 다: RDB 판정 → `OtlpProcessor`. receipt ID·수신 시각은 message ID·접수 시각이다.
   재시도·offset 은 listener 와 오류 처리기가 소유하고 코어 안에 재시도 루프를 두지 않는다. 전체 흐름을 하나의 `@Transactional` 로 감싸지 않는다.
4. **공유 모듈**(모듈 지도 4절 — 앱끼리 의존하지 않고 정의가 갈라지면 안 되는 코드는 `:libs:` 로 올린다)

   | 모듈 | 패키지 | 담는 것 | 의존 |
   |---|---|---|---|
   | `:libs:telemetry-otlp-http` | `telemetry.otlp` | OTLP/HTTP 응답 본문·`GrpcCode`·signal 경로·media type·Content-Encoding 허용 목록·405/404/413/415/401 본문 | protobuf-java |
   | `:libs:telemetry-ingress-contract` | `telemetry.ingress` | envelope `.proto`·codec·`AcceptedTelemetry`·`GatewayAuthContext`·`RawOtlpPayload`·Kafka 접속 설정·record key·로그 이벤트 형식 | protobuf-java · otlp-http |
   | `:libs:telemetry-auth` | `telemetry.auth` | telemetry JWT 발급·검증·키 로더·Bearer 추출 | nimbus |

   셋 다 Spring·JPA·Kafka 에 의존하지 않는다. 응답 본문을 옮겨도 바이트는 그대로다(`OtlpResponsesTest`).
   Gateway 는 `:libs:telemetry-collector`(S3 SDK)·`:libs:security`(JPA)에 의존하지 않는다.
5. **패키지**: 이 컨텍스트에 배포 단위가 둘이 되어 모듈 지도 3절의 내림 조항이 발동한다. Gateway 는 처음부터 `telemetry.gateway` 를 쓴다.
   ingest 의 기존 패키지(`telemetry.api`·`config`·`pipeline`)를 `telemetry.ingest` 로 내리는 기계적 rename 은 이번에 하지 않는다 —
   두 앱이 서로 다른 하위 패키지만 공급해 패키지 유일성(ADR 0008 규칙 2)이 깨지지 않는다.

## Alternatives Considered

### A. Consumer 가 `OtlpHttpRequest` 를 만들어 기존 핸들러를 부른다
- 장점: 수집 모듈을 고치지 않는다.
- 단점: 처리 결과를 HTTP 상태로 해석하고, 재시도마다 새 UUID·현재 시각이 receipt 가 된다.
- 탈락 이유: row version·ledger 키가 시도마다 달라진다.

### B. Consumer 스레드에서 `SecurityContextHolder` 를 채운다
- 장점: `IdentitySource` 를 그대로 쓴다.
- 단점: 스레드 지역 상태가 재시도·예외 경로에서 남거나 빠진다. 신원이 빠져도 스탬프 없이 지나간다.
- 탈락 이유: 신원은 필수 인자여야 빠졌을 때 컴파일·생성 단계에서 막힌다.

### C. `SignalConsumer` 앞에 producer 를 붙인다
- 탈락 이유: 그 지점은 이미 마스킹·아카이브가 끝난 뒤다. Kafka 경계는 디코딩 전이어야 Gateway 가 본문을 해석하지 않는다(ADR 0066).

### D. Gateway 가 `:libs:telemetry-collector` 에 의존한다
- 탈락 이유: S3 SDK·마스킹·디코더가 접수 경로의 클래스패스에 오른다. 응답 본문만 필요하다.

## Consequences/Tradeoffs

### Positive
- HTTP·Kafka 가 같은 코어를 지난다. 상태 매핑은 HTTP 어댑터, 재시도·offset 은 Kafka 어댑터 한 곳씩이다.
- 재시도에도 receipt ID·수신 시각이 같아 분석 행의 row version 이 수렴한다.
- 신원이 빠진 호출이 생성 단계에서 막힌다.

### Negative
- `:libs:` 모듈이 셋 늘었다. ADR 0016 Follow-up 의 ArchUnit 도입 조건("`:libs:` 모듈이 하나 더 늘면")이 충족됐지만 이번에는 도입하지 않는다 — 사람이 확인했다.
- 인증 없이 핸들러를 부르던 테스트 경로가 사라져 수집 모듈 테스트가 고정 신원을 넘겨야 한다. 신원 없는 스탬프 규칙은 `IdentityStamperTest` 가 직접 고정한다.
- ingest 패키지 rename 이 남는다.

## Follow-up

- ArchUnit 도입(ADR 0016 Follow-up) — 조건이 충족됐다. 스테레오타입 부재·패키지 유일성·간선 방향을 기계 검사로 옮긴다.
- ingest 패키지를 `com.team376.pulsemetry.telemetry.ingest` 로 내린다(모듈 지도 3절).
- 허브 ADR 0005 의 "신원은 `SecurityContextHolder` 에서 얻는다"를 이 ADR 기준으로 고친다(허브 범위).
